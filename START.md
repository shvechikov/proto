# START — для ИИ-агента

Тебе дали ссылку на этот репозиторий и попросили начать новый проект по методу proto или подключить метод к существующему проекту. Этот файл — порядок действий. Человек, который тебя попросил, дальше называется **автором**. Он может быть опытным разработчиком или никогда не писать код. Говори с ним на языке продукта.

## 0. Прочитай метод

Если репозитория метода ещё нет на диске, склонируй его во временную папку, не в проект: `git clone --depth 1 {ссылка} {временная папка}`. Читай файлы оттуда: пересказ веб-страницы теряет детали. Запомни коммит (`git rev-parse --short HEAD`) — он попадёт в AGENTS.md проекта.

Прочитай:

- **сейчас:** `method/principles.md`, `method/collaboration.md`, `method/documents.md`, `method/workflow.md`;
- **перед тем как писать AGENTS.md проекта:** `agent/instructions.md`;
- **перед первым кодом:** `method/testing.md` и `stacks/tauri2.md` (стек по умолчанию).

## 1. Пойми, где ты

- **Папка пустая** (или в ней только пара файлов автора) → новый проект, шаги 2–7.
- **Есть код или документы** → подключение к существующему проекту, раздел в конце. Без согласия автора ничего не перестраивай.

## 2. Онбординг: цель, фокус, рамки

Это разговор, а не анкета.

- Задавай по одному вопросу и к каждому предлагай свой рекомендуемый ответ, чтобы автор мог ответить «да».
- Что уже ясно из первой просьбы, не спрашивай — подтверди одной фразой.
- Бюджет «три вопроса за сессию» на онбординг не распространяется, но уложись примерно в 6–8 вопросов.
- Слова автора записывай дословно: они пойдут в первую запись журнала.

Что нужно узнать:

1. **Цель** — что изменится и для кого, если проект удастся.
2. **Пользователи** — сам автор, семья, друзья, клиенты. Что они делают сейчас без этого продукта.
3. **Фокус** — одна главная вещь первой версии.
4. **Рамки** — чего точно не делаем. Ограничения: платформы (Mac, Windows, iPhone, Android, веб); личные данные — чьи они и где живут; деньги; сроки; аппетит — сколько внимания автор готов тратить.
5. **Как поймём, что получилось** — наблюдаемый сигнал и порог («правы, если…»).
6. **Режим работы** — предложи его сам по ответам:
   - **продукт** — одно приложение, которое растёт; единица работы — изменение;
   - **лаборатория** — много гипотез и одноразовые прототипы рядом; единица работы — эксперимент со своим кодом в `lab/NNN-slug/`.
7. **Язык документов** — по умолчанию язык разговора.

Про технику (стек, библиотеки, архитектуру) не спрашивай: реши сам по `stacks/` и запиши в решения. Исключение — если автор назвал технологию сам. Стек по умолчанию — Tauri 2. Если хватит сайта, это тот же скелет без оболочки.

Перед тем как создавать файлы, перескажи автору замысел пятью-семью строками и получи «да».

## 3. Скелет

Скопируй в проект:

| Откуда (репозиторий метода) | Куда (проект) |
|---|---|
| `templates/` — всё, включая `.claude/` | корень проекта |
| `method/*.md` | `docs/method/` |
| `agent/instructions.md` | `docs/method/agent.md` |
| `stacks/tauri2.md` (или выбранный стек) | `docs/method/stack-tauri2.md` |
| `agent/skills/harmonize/` | `.claude/skills/harmonize/` |
| `agent/check-docs.mjs` | `scripts/check-docs.mjs` |

Заполни по итогам онбординга:

- `docs/product.md` — замысел;
- `docs/roadmap.md` — «Сейчас» (первая работа), «Дальше» и «Потом» — что прозвучало;
- `docs/decisions.md` — первые решения с сегодняшней датой: режим, стек, язык и всё, что автор решил в разговоре;
- `docs/questions.md` — что осталось открытым, если осталось;
- `docs/model.md` — главные понятия продукта, если они прозвучали. Если нет, удали файл: он появится позже;
- `AGENTS.md` — заполнители `{…}`, ссылка на метод и коммит, «Уже решено». Пока кода нет, вместо `{команда check}` — `node scripts/check-docs.mjs`;
- `README.md` проекта.

Правила:

- Ни одного незаполненного `{…}`: что заполнить нечем, удали.
- Пустых файлов и папок не создавай. `docs/testing.md`, `docs/architecture.md` и `docs/inbox.md` появятся, когда будет что в них писать.
- Файлы в `docs/method/` не правь: отклонения проекта записываются в AGENTS.md → «Диалект».

## 4. Первая карточка

`docs/work/001-{slug}.md` по шаблону `docs/work/_template.md`. Это самый маленький шаг, после которого автор сможет что-то потрогать: вертикальный срез, на экране, с настоящими понятиями продукта. Для приложения в этот срез входит каркас стека по `docs/method/stack-tauri2.md`: `core/`, `src/platform/`, оболочка, `check`, первые тесты.

## 5. Git

- `git init`, если репозитория ещё нет.
- `.gitignore`: папки данных, секреты, сборки.
- Если git не настроен, спроси имя и почту для коммитов.
- Первый коммит делай после того, как автор посмотрел структуру.

## 6. Закрой сессию

- Запись `docs/journal/{ГГГГ-ММ-ДД}-start.md`: слова автора из онбординга дословно и что создано.
- Автору коротко: что создано, что дальше (первая карточка) и не больше трёх вопросов, если они есть.
- Предложи начать первую карточку.

## Подключение к существующему проекту

1. Прочитай, что есть: README, инструкции для агентов, документы, структуру кода, `git log`.
2. Составь карту: какой существующий документ играет какую роль из `method/documents.md` и чего не хватает.
3. Предложи автору минимум, который даст больше всего. Обычно это:
   - тонкий AGENTS.md по `agent/instructions.md`;
   - «Сейчас» в одном месте;
   - журнал сессий;
   - журнал решений;
   - `check`.
4. С согласия автора скопируй `docs/method/`, skill и `scripts/check-docs.mjs`, как в шаге 3. Существующие документы не переименовывай и не переноси без отдельного согласия.
5. Всё, в чём проект отличается от метода, запиши в AGENTS.md → «Диалект».

## Обновление метода в проекте

Если автор просит «обнови метод»:

1. Склонируй свежий репозиторий метода.
2. Сравни с `docs/method/` и прочитай `CHANGELOG.md` с коммита, записанного в AGENTS.md.
3. Покажи автору, что изменилось, и после согласия замени `docs/method/` целиком.
4. Обнови коммит в AGENTS.md.
5. Проверь, не противоречит ли что-то «Диалекту».
