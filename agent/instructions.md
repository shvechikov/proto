# Обвязка агента: AGENTS.md, skills, хуки, проверки

Слой 2 метода: как превратить правила метода в то, что агент действительно выполняет. Рассчитано на Claude Code, но канонический файл — `AGENTS.md`. Его читают и другие агенты: Codex, Cursor, Gemini и прочие. `CLAUDE.md` содержит одну строку `@AGENTS.md`. Новые версии Claude Code читают AGENTS.md и без неё, но с импортом надёжнее в облачных и старых сессиях.

## Что известно на 2026 год

- **Файл-инструкция загружается в каждую сессию** и каждый раз стоит токенов. Исследование ETH Zurich ([Gloaguen et al., 2026](https://arxiv.org/abs/2602.11988)) показало:
  - в среднем такие файлы не повышают успешность задач, а стоимость работы растёт больше чем на 20%;
  - файлы, сгенерированные самой моделью, вредят;
  - обзоры репозитория бесполезны;
  - помогают нестандартные правила и явно названные команды.
  - Агенты инструкциям следуют, поэтому лишняя инструкция не безвредна.
- **Документация Claude Code** ([memory](https://code.claude.com/docs/en/memory)): файл короче 200 строк. `@import` контекст не экономит, импортированное тоже грузится сразу. Блочные HTML-комментарии `<!-- -->` вырезаются до загрузки, так что в них можно писать заметки для людей бесплатно.
- **Правило — это просьба, проверка — гарантия.** Всё, что должно выполняться всегда, надёжнее поручить хуку, тесту или линтеру.

## Что класть в AGENTS.md

- **Как подхватить работу** — пять строк со ссылками.
- **Команды** — `check`, запуск, сборка — ровно так, как их набирать.
- **Договорённости с автором** — коротко, со ссылкой на метод.
- **Нестандартные правила и грабли**, которые агент не выведет сам.
- **Безопасность данных:** где настоящие данные и что с ними нельзя делать.
- **«Уже решено»** — действующие решения, по строке с датой.
- **Где что** — ссылки на документы, у каждой одна фраза. Агент читает их по необходимости.
- **Диалект** — отклонения проекта от метода и почему.

## Чего не класть

- Обзор проекта и структуру файлов «на всякий случай»: агент найдёт сам.
- Статус: он живёт в «Сейчас».
- Пересказ метода: достаточно ссылки на `docs/method/`.
- Общие советы, которые агент выполняет и так («пиши чистый код», «думай о безопасности»).
- Восклицательные знаки и КАПС на каждом правиле. Выделить можно одно правило, а не десять.

**Размер:** до ~150 строк и ~12 КБ. Русский текст дороже английского в токенах, поэтому следить нужно и за байтами. `scripts/check-docs.mjs` проверяет оба предела.

## Как растут правила

| Что случилось | Что добавить |
|---|---|
| Агент повторил ту же ошибку | Строку в AGENTS.md; дату и причину — в HTML-комментарий рядом |
| Записанное правило нарушено | Проверку: тест, линтер или хук |
| Одну и ту же процедуру объясняешь в третий раз | Skill (`.claude/skills/<имя>/SKILL.md`) |
| Правило касается только части кода | AGENTS.md в этой папке или `.claude/rules/` с полем `paths:` |
| Сменилась модель | Пройтись по правилам и удалить то, что агент теперь делает сам |

Правила появляются в ответ на настоящие ошибки, а не заранее. Чужие наборы правил целиком не копируем.

## Направляющие и датчики

|  | До действия — направляющие | После действия — датчики |
|---|---|---|
| **Детерминированные** | Шаблоны, скрипты, генераторы | Тесты, линтеры, проверка ссылок, хуки |
| **На суждении ИИ** | AGENTS.md, skills | Ревью свежим субагентом, гармонизация |

Где можно, выбираем детерминированные датчики. Набор по мере роста проекта:

1. **Сразу:**
   - `check` включает `node scripts/check-docs.mjs` — проверку того, что ссылки между документами живы, а AGENTS.md и CLAUDE.md не разрослись;
   - хук на старте сессии (ниже).
2. **Когда появятся настоящие данные:** ограждение, которое не даёт агенту писать в них напрямую. И отдельная `dev`-сборка, которая физически их не видит (подробности — в описании стека).
3. **Когда появятся слои в коде:** архитектурные границы как проверка. Например, «ядро не импортирует интерфейс» или «эксперименты не импортируют друг друга» — для TypeScript через [dependency-cruiser](https://github.com/sverweij/dependency-cruiser). Сообщение об ошибке должно объяснять, как её исправить.
4. **На вехах:** гармонизация (`/harmonize`), `/doctor prompt-audit` в Claude Code и мутационный прогон ядра.

## Хуки Claude Code

Хуки лежат в `.claude/settings.json` проекта и выполняются всегда, что бы агент ни решил.

**Начало сессии** — показать «Сейчас» и последнюю запись журнала. Срабатывает при запуске, при продолжении и после сжатия контекста. Текст, который печатает команда, попадает в контекст агента:

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume|compact",
        "hooks": [
          {
            "type": "command",
            "command": "cd \"$CLAUDE_PROJECT_DIR\" && sed -n '/^## Сейчас/,/^## Дальше/p' docs/roadmap.md && echo \"Последняя запись журнала: $(ls docs/journal 2>/dev/null | tail -1)\""
          }
        ]
      }
    ]
  }
}
```

**Ограждение** (`PreToolUse`, matcher `Edit|Write`) — скрипт получает JSON на stdin, путь к файлу лежит в `.tool_input.file_path`. Код выхода 2 запрещает действие, а текст из stderr агент видит как причину. Пример `.claude/hooks/guard.sh` (нужен `jq`):

```sh
#!/bin/sh
# Настоящие данные — только через приложение; прошлые записи журнала не правятся.
input=$(cat)
f=$(printf '%s' "$input" | jq -r '.tool_input.file_path // empty')
tool=$(printf '%s' "$input" | jq -r '.tool_name')
case "$f" in
  */data/*)
    echo "Настоящие данные меняются только через приложение и по просьбе автора." >&2; exit 2 ;;
  */docs/journal/*)
    if [ "$tool" = Edit ]; then
      case "$(basename "$f")" in "$(date +%F)"*) ;; *)
        echo "Прошлые записи журнала не правятся — добавь новую." >&2; exit 2 ;;
      esac
    fi ;;
esac
exit 0
```

**Проверка перед концом хода** (`Stop`) — запускать `check`, если менялся код. Включать, только когда `check` быстрый (меньше минуты). Иначе каждый ход, даже разговорный, будет ждать.

## Память агента

Claude Code ведёт автопамять вне репозитория (`~/.claude/projects/…/memory/`). Это удобно для личных привычек автора, но противоречит принципу «всё важное — в репозитории». Правило: всё, что касается проекта, записывается в документы проекта. Если агент что-то «запомнил» о проекте, на обзоре это переносится в документы. Отключить автопамять для проекта можно настройкой `autoMemoryEnabled: false`.
