## Подхват работы

1. `docs/roadmap.md` → «Сейчас», затем «Сейчас» в карточке активной работы.
2. Последняя запись `docs/journal/`, `docs/questions.md`.
3. `git status`, `git log --oneline -10`. Незакоммиченное чьё-то: понять, не выбрасывать.
4. `{команда check}`. Зелёная — можно работать.

Перед первой правкой в сессии прочитай `docs/method/workflow.md`: размер задачи, срезы, закрытие.

## Договорённости с автором

- «Давай обсудим», «пока ничего не меняй» — только разговор: ни кода, ни данных, ни документов.
- Ясная просьба — делать сразу. Если перед длинной автономной работой есть сомнения, сначала вопросы.
- Автор решает «что и зачем», агент — «как». Вопросы — только о том, что решает автор: не больше трёх новых за сессию, каждый с рекомендуемым ответом (`docs/method/collaboration.md`). Остальное — консервативный выбор, записанный в решения.
- Перед работой назови размер: мелочь, изменение или большой шаг.
- «Готово» — значит показано: вывод `check`, скриншот.
- Слова автора — в журнал дословно.
- Закрытие — по чек-листу `docs/method/workflow.md` → «Закрытие».

## Данные и безопасность

- Настоящие данные: {где живут}. В git и тесты они не попадают. Менять их — только по просьбе автора и через приложение.
- Тесты и разработка работают на демо-мире.
- Секреты — никогда в git.
- В коммит — файлы по именам. Перед разрушительной операцией в git — `git diff`.
- Публикация, развёртывание и любые отправки наружу — только по слову автора.
- Всё важное о проекте записывается в документы репозитория, а не в память агента.
